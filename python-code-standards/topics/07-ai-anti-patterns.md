# AI 代码质量 — 反模式检测

> 来源：改编自 Anchor（MIT）· python-agents-rules（Section 34）。

## 目标与边界

**做**：教 AI 识别自己/同类最容易犯的三类代码病：偷懒、困惑、膨胀。

**不做**：
- ❌ 不重复完整质量清单（见 `python-code-quality-standards`）

## 34.1 Think First — 写码前先思考

写任何代码前必做：读相关现有代码 → 说明你的方案与理由 → 指出集成点 → 查有没有现成工具。**如果你说不出为什么选这个方案，先停下来想。**

## 34.2 偷懒信号（LLM 常见捷径）

| 模式 | 样子 | 为什么坏 |
|------|------|---------|
| 空洞测试 | `assert True`、无断言测试 | 虚假安全感 |
| 过宽类型 | `Optional[T]` 泛滥、`Any` 进签名 | 隐藏空值契约，废掉类型检查 |
| Catch-n-log | `except Exception: logger.error(...)` 不重抛 | 吞错误，系统处于未定义状态 |
| 无理解复制 | 照抄本地模式不知为何存在 | 传播反模式 |
| 多余 helper | 只被引用一次的小函数 | 增加间接层，不降复杂度 |
| bool 参数 | `foo(True, False)` | 调用点不可读 |
| 为已删逻辑写测试 | 测不存在的行为 | 空洞通过，零价值 |

## 34.3 困惑信号 — Agent 不确定时的迹象

- "这是 3 种修法…"（试了很多，没把握）
- 过度防御代码（5 层 null 检查、验证已验证数据）
- 处处 try/except（不知道哪些操作真的会挂）
- 冗余空值检查（对构造上永不 None 的值判 None）
- 往 god object 加方法（不动脑就往大对象塞）

**补救**：停 → 重读相关抽象 → 找代码库里的相似范式 → 真不懂就问用户；**别用防御代码粉饰困惑**。

## 34.4 膨胀信号 — 不必要的添加

- 注释讲"我改了啥"不讲"代码为啥这样"
- 15 个测试测同一 happy path 不同输入（测边界：空/单个/多个/错误/边界即可）
- `logger.info("Entering function")` 全量日志
- 把每个常量都做成可配置
- 为"以后"加 hooks/接口/扩展点 → YAGNI

## 34.5 代码规模上限

| 界限 | 阈值（不含测试） |
|------|------------------|
| 函数 | 50 行 |
| 模块 | 500 行 |
| 文件 | 800 行 |
| 类 | 300 行 |

超限时按"内聚的职责组"拆新模块——不要字母序/随意拆。

## 34.6 平台要求

除非明确说明，Python 代码需跨 Linux/macOS/Windows：用 `pathlib.Path`、`tempfile`，不硬编码 `/tmp`，不用 `os.fork`；OS 专属特性用 `sys.platform` 守卫并记录。

## 注意事项

- AI 是提议者也是自己代码的质量过滤器——提交前必须先自查这四张表
- 打回代码时引用具体模式，不要只说"写得不好"
